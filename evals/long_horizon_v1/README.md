## Offline native child lineage ledger

The pinned desktop CLI v0.158 rollout represents a reused native child as one
`session_meta` and an ordered sequence of turns. The parent records one
`spawn_agent` call, `SubAgentActivity.started`, and the spawn result. A
`send_message` call, `interacted` activity, and empty result add an input to
the active child turn. After that turn's terminal and matching parent
`subagent-completed-<child-turn-id>` activity, a `followup_task` call,
`interacted` activity, and empty result trigger a new turn on the same child
session. Each child turn has `task_started`, `turn_context`,
`inter_agent_communication_metadata.trigger_turn`, a routed `agent_message`
with `internal_chat_message_metadata_passthrough.turn_id`, and its own terminal.
The child `root_turn_id` must match the parent turn that issued its own
`spawn_agent` or `followup_task` trigger. Pilot-07 issued both triggers in the
same parent turn; a later parent turn is also supported. Every explicit
function result thread and turn identity is checked against its call. The
encrypted routed input is compared by SHA-256 commitment
against the corresponding parent call argument; neither value is retained in
the ledger. `native_lineage(..., closed_snapshot=True)` requires every turn to
close with one exact parent completion. Its default live-prefix mode permits
an unfinished final turn while rejecting contradictory observed identities.
For a child `turn_aborted` with reason `interrupted`, closed mode accepts the
absence of normal completion activity only when the caller supplies a trusted
`interruption_proof` with exact child-first interrupt targets, acknowledged
requests, matching parent and child aborted terminals after dispatch, and
reconciled session usage and drain. The ledger marks this closure
`interrupted`; it never creates a completion activity. Without that proof,
closed lineage has an issue and cost status remains unknown.
